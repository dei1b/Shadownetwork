## Data Reset and Reinstallation Policy

Do not clear application data as a normal upgrade step. Schema changes must use sequential SQLite migrations and preserve existing messages, peers, conversations, SCF envelopes, and moderation state.

Use the following rules:

- Database migration only: install over the existing app and verify preserved rows. Do not clear data.
- New readable payload schema: update reader support before switching writers. Mixed-version devices may operate only according to `PROTOCOL_COMPATIBILITY.md`.
- Transport protocol version change: all test devices must run compatible transport versions before a multi-device trial.
- Trust-bundle schema or signing-key change: import the new bundle; clearing the entire app is not required.
- Device key loss or deliberate key reset: re-register the device, approve its replacement public key, and publish a new trust bundle.
- Application ID or signing identity change: expect Android identity and storage behavior to differ; document the change and re-register affected devices.
- Factory reset or Android user/signing changes: the application peer ID may change; register the newly displayed device ID.
- Destructive development reset: allowed only for an isolated test device after exporting needed evidence and explicitly recording the reset.
